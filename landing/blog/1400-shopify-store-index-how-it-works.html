How the 1,400 Shopify Store Index Works — Technical Deep Dive

Under the StoreScope UI is a data pipeline that turns raw /products.json feeds from ~1,400 Shopify stores into a weekly ranked list of trending product clusters. Here's the full path.

Stage 1 — Store discovery

The index starts with a hand-curated seed list of Shopify stores, expanded weekly by 3 sources:

  • Public store directories that publish Shopify-hosted URLs
  • Cross-reference through supplier catalogs (a store carrying supplier X often shares other stores)
  • Manual QA — merchants with private stores or noindex are excluded per robots.txt

Current: 1,400+ active stores. Coverage bias: US/EU/AU focus (Shopify's primary markets), retail categories (fashion, tech accessories, home, fitness).

Stage 2 — Product feed crawl

Each store exposes /products.json — a public JSON endpoint Shopify provides for storefront APIs. StoreScope's crawler:

curl_cffi AsyncSession (Chrome TLS fingerprint)
+ asyncio.Semaphore(CONCURRENCY=15)
+ robots.txt respect (per RFC 9309)
+ 20s timeout per request
+ retry with exponential backoff on 429/503

Result: 140,000+ product records per weekly cycle. No auth bypass, no scraping — public endpoint only. Any merchant can block via robots.txt (respected).

Stage 3 — Perceptual image hashing (pHash)

Same product across stores often has:

  • Different titles (translated / rewritten)
  • Different SKU numbers (per-store)
  • Different pricing (per-store margin)
  • But same physical item image (from same supplier)

Text matching fails on this. Image hashing succeeds. StoreScope uses perceptual hashing (pHash) which is robust to:

  • Small resolution changes (Shopify's srcset variants)
  • Compression artifacts (JPEG quality differences)
  • Watermarks, minor crops
  • Color shifts within 10-15% (different lighting)

Hamming distance ≤ 6 (out of 64-bit hash) treats images as same product.

Stage 4 — Clustering

Products with matching pHash form a cluster. Each cluster tracks:

  • Store count (distinct stores carrying the product)
  • Price min/max/median across stores
  • First seen date (cluster age)
  • Week-over-week store delta (growth rate)

Current: 1,600+ active clusters (product groups with ≥ 2 stores).

Stage 5 — Storm Score V2 ranking

The ranking is where StoreScope differs from bestseller lists. Storm Score V2 combines:

Storm Score = w1 · log(store_count)
            + w2 · momentum(EMA + Kalman-gated)
            + w3 · age_decay(exp(-λt))

Momentum via Kalman-gated EMA

Simple exponentially-weighted moving average of weekly deltas gets skewed by outlier weeks (Black Friday spikes, data errors). Kalman filter innovation gating rejects outliers before smoothing:

innovation = |Δ_current - Δ_prediction|
if innovation > 3σ: reject as outlier
else: update EMA

Result: momentum score reflects real trend velocity, not noise.

Age decay

Clusters older than 8 weeks (peaks already known) get exponentially discounted:

age_factor = exp(-0.15 · weeks_since_first_seen)

Result: rising 4-week-old clusters outrank saturated 6-month-old giants.

Stage 6 — Weekly digest generation

Every Monday at 9 AM UTC (subscriber's timezone-normalized):

  1. Query top N clusters by Storm Score (N=20 Starter, unlimited Pro)
  2. Attach: representative image, store count, price spread, week delta, momentum score
  3. Link: all stores carrying each cluster (for margin research)
  4. SMTP send with unsubscribe token (HMAC-SHA256, 8-byte)

Compliance

  • robots.txt respected — merchants can opt out
  • Public data only — same as any shopper sees
  • No PII stored — product data + store domain, nothing else
  • GDPR — subscriber email + weekly digest consent (opt-in), unsubscribe 1-click
  • Korea 정보통신망법 §50 — unsubscribe link in every email footer

What the data can and can't tell you

Can:

  • Which products are being tested at scale (cluster growth signal)
  • Category trends over time (rolling snapshots)
  • Supplier concentration (many stores + tight price spread)
  • Entry timing (rising vs peaked)

Can't:

  • Individual store's sales volume (public feed doesn't expose)
  • Ad spend / customer acquisition cost (not in product data)
  • Fulfillment quality / return rates (private data)
  • Real-time trend detection (weekly refresh only)
